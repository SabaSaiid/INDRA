# INDRA AI/ML limitations and prohibited claims

1. All six frozen components have project-controlled **synthetic development** evidence. None has representative field validation, field calibration, or production-readiness approval. Synthetic metrics must never be reported as deployment accuracy.
2. Phase 18 NLP predicts only `URBAN_FLOOD`, `RIVER_BREACH`, `CLOUDBURST`, `CYCLONE_INUNDATION`, and `NOT_RELEVANT`. Rainfall, thunderstorms, heatwaves, fog, dust storms, and strong wind are broader SIH examples or future ontology, not current trained classes.
3. Phase 20 is deterministic event grouping, not a learned event classifier. Its original benchmark still does not prove template- and parameter-family-disjoint splits; a separate Phase 20R benchmark has been formally `REVALIDATED` with distinct synthetic families and a one-shot test. That synthetic result is not field event-detection accuracy. A single report remains `CANDIDATE`, not `CONFIRMED`.
4. Phase 21 credibility estimates misleading-risk evidence on synthetic data; it does not authenticate a report or estimate a calibrated truth probability. Duplicates and anomalies are not fake reports.
5. Phase 22 image analysis uses a local scratch CNN, but synthetic images do not prove performance on citizen phone images, compression, lighting, or real disaster scenes. Missing image input is explicit, not a zero score.
6. Phase 23 separates `DATA_QUALITY_ANOMALY` and `WEATHER_BEHAVIOR_ANOMALY`. The 34/62 direct scenario-discriminating features imply `SYNTHETIC_GENERATOR_DEPENDENCE=HIGH`; no retuning or field-generalization claim follows.
7. All six components are connected in the tested backend code as **advisory** `UnifiedMLResult` evidence. The legacy fusion score and human-review state do not consume synthetic model scores as automatic truth. A stored media URL supplies no image bytes; absent image/history is `NOT_RUN`, not a negative result.
8. Model inference has no network dependency or pretrained/open-weight checkpoints. Backend infrastructure, including PostgreSQL, Kafka, Redis, and weather APIs, may use networking; do not conflate that with model inference.
9. Phase 25R and Phase 26 passed against a dedicated local native PostgreSQL/PostGIS and Redis-compatible test stack. This is repository integration evidence, not production field validation. The eight remaining backend skips are pre-existing tests for unavailable legacy embedding/fallback branches, not infrastructure-dependent tests hidden from the run.

Historical MiniLM, 14-class NLP, Isolation Forest, classical-only image, and "no trained models" descriptions elsewhere in the repository are dated planning/audit snapshots. For current ML state, use the [architecture](ML_ARCHITECTURE.md), [model card](ML_MODEL_CARD.md), [data card](ML_DATA_CARD.md), [inference contract](ML_INFERENCE_CONTRACT.md), and [validation report](ML_VALIDATION_REPORT.md).
